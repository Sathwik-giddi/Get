# Design review 003

Date: 2026-10-02
Scope: replacing the Streamlit front end with React and Vite, and re-running the gate
Direction: `DESIGN.md`, unchanged

## Why the front end moved

Streamlit was chosen for speed during the first build: no build step, one Python file, and a
predictable launch. It cost more than it saved, and the bill came due in `audit-002`:

- Streamlit's emotion cache applies `font-size: inherit` to `p` at specificity 0,1,1, which
  silently beat every custom rule at 0,1,0. The one element the design names as its focal
  point rendered at 16px instead of 33px, and the only reason it was caught was measuring the
  rendered page instead of reading the stylesheet.
- Raw HTML had to be assembled as f-strings to draw the trace rail, which meant fighting
  Markdown escaping on top of fighting the CSS.
- Every widget interaction re-runs the whole script, so `/health` and `/audit` are refetched on
  every keystroke in the scenario box.
- `st.metric` cannot express the design, so the header metrics were replaced with hand-written
  HTML, which is a sign the framework has been outgrown rather than an improvement.

None of that is fixable from inside Streamlit. Moving the view to React while keeping the
FastAPI contract untouched is the change with the best ratio of cost to benefit.

## Defects found and fixed during the migration

All four were caught by the gate running against the real app, not by reading the diff.

- **`<div>` inside `<p>`.** The run metadata block nested divs in a paragraph element. React
  logged a hydration warning that the browser was silently repairing. Fixed by making the
  container a div. The gate now fails on any console error.
- **The sidebar was zero width.** The grid template read a variable that was set to `0px`, so
  the rail collapsed and the whole layout overlapped itself. Visible immediately in the
  first screenshot after the move.
- **The remove button printed its own label.** `Remove IMG_4471_bridge.jpg x` rendered as
  visible text inside the file row, overflowing the 344px rail. Fixed by moving the label to
  `aria-label` and leaving only the glyph visible, with a 44px target.
- **The primary button was 40px tall.** Below the 44px tap target floor, and the test caught it
  as a 40px `<select>` first.

## Added in the move

- A skip link, so a keyboard user reaches the decision without walking the sidebar. The gate
  asserts it is the first tab stop.
- Real `<label>` elements for every control, a `<caption>` on the audit table, `aria-live` on
  the progress region, and `role="meter"` with values on the confidence bar. Streamlit gave none
  of this for free.
- The four viewports the gate walks are now 390, 768, 1280 and 1600, up from three.

## Delivery Gate

- Block 1: unchanged from `audit-002` except the interface it measures. R-25 pass on all
  fourteen roles, R-27 pass with empty, loading and three distinct failure paths, R-32 pass with
  the skip link first and a 3px focus ring measured by keyboard traversal, R-03 pass at four
  widths, R-25 non-text pass with all targets at 44px, R-35 pass because the gate drives the
  real browser, R-38 pass because mock mode still announces itself in words.
- Block 2: nothing in the Purpose-Gate list gained an exception. There are still no gradients,
  no icons, no shadows, no badges, no glass and no background pattern.
- Block 3: dials unchanged. The call is still the only focal point at 42px against 17px for a
  chain claim. The trace rail survives the migration as the identity motif.
- Block 4: the composition is unchanged, so R-05, R-11, R-15, R-16, R-20, R-29 and R-30 carry
  over from `audit-002` without re-litigation.

## Dead code removed

`ui/` and `tests/test_gate.py` are deleted rather than left behind. Keeping a second front end
in the repository during a hackathon is how the demo gets pointed at the wrong process.

`agent/gemini.py` still carries four `# type: ignore[return-value]` suppressions in
`MockProvider.generate`. Still out of scope for this skill, still noted.
