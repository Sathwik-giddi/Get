# Design review 004

Date: 2026-10-03
Scope: everything new since `audit-003`: the duty-officer panel (`web/src/components/Officer.jsx`),
the override endpoints (`api/main.py`, `agent/audit.py`), the eval harness copy, and the README
additions. The rest of the UI was gate-verified in `audit-003` and is not re-litigated here.
Mode: audit after. Nothing below has been fixed yet.

Design Read (unchanged): *operations console for a duty officer who must act or escalate in
under 30 seconds, procedural language, dials ENERGY 2 / RHYTHM 2 / MOTION 1.*

Priorities follow the rule tier: Hard Gate is HIGH, Purpose-Gate is MEDIUM, Quality Locks
are LOW.

## Findings

### 1. Accept and Override look identical, but only one of them destroys — R-31, C-1 — MEDIUM

`Officer.jsx:89-96`. Both buttons use the same `quiet` class, the same size, the same weight.
Accept confirms the machine. Override replaces a recorded verdict with one click and no
further step. Two actions with opposite consequences share one visual voice, and there is no
written reason for that choice, because there is no good one. The design already knows how to
mark weight: the accent marks the call, the hairline marks everything else. The override
control should carry visible weight of its own, and the accept control should stay quiet.

### 2. The ruled note stays in the box after recording — C-2, C-4 — MEDIUM

`Officer.jsx:78-87`. After a successful accept or override, the verdict note remains in the
textarea. The status box above already shows it, so the same sentence now exists twice on
screen, and the stale copy invites an accidental second recording. Standard form behavior is
to clear the field on success. The fix is one line in `act()`.

### 3. The audit table does not show the verdict — C-3 — MEDIUM

The sidebar history lists run, time, and confidence, but nothing marks which runs carry an
officer ruling. The trail is recorded (`override` merges into every audit row) yet invisible
exactly where history is read. An officer scanning eight runs cannot tell ruled from unruled
without opening each one. The table already fetches rows that contain the verdict; it only
needs to show it. This is the same class of gap `audit-001` finding 4 belonged to: the state
exists, the screen does not say it.

### 4. Dead `refresh()` in Officer.jsx — out of scope, noted — LOW

`Officer.jsx:39-45`. Defined, never called; the `useEffect` above does the loading. This is
code, not comments, so the comments skill does not cover it, and it is recorded here the same
way `audit-001` recorded its out-of-scope items: harmless, worth deleting in the same pass.

### 5. Inline styles instead of classes — R-31 — LOW

`Officer.jsx:78` and `:99` use `style={{ marginTop: 12 }}`. The stylesheet owns spacing
everywhere else on the page. Two one-off values with no reason to differ from the system.
Move them into `styles.css`.

### 6. The note field is unbounded — C-4 — LOW

`Officer.jsx:80-86`. No `maxLength`, no visible limit. An officer can paste anything, and the
audit row stores all of it. Cap the field at 500 characters with the limit visible, so the
constraint is stated before it is hit rather than discovered after.

### 7. DESIGN.md does not cover the officer surface — R-37 — LOW

`DESIGN.md` describes the call, the rail, and the reference column. The duty-officer section
arrived later and follows the tokens, but no line anywhere says what it is for, which action
carries weight, or where the verdict surfaces. Direction exists for the page but not for this
section. Any fix to findings 1 through 3 should add the entry at the same time.

## Not findings

- Copy in the panel passes: "Accept the call" and "Override the call" name their actions,
  "Recording again replaces this entry" states the consequence before it happens, and the
  empty state ("No officer has ruled on this run yet") names the state plainly. No triads, no
  buzzwords, no dashes, no emoji, verified by scan.
- Contrast needs no re-verdict: every element in the panel reuses measured roles (eyebrow,
  hint, note, quiet button, textarea). The gate will still gain officer selectors so a future
  regression cannot hide behind reuse.
- Keyboard needs no re-verdict: label, textarea, and both buttons are native controls in DOM
  order, and the gate walks them. The fix batch extends the tap-target check to the new
  buttons, which already clear 44px by the shared rule.
